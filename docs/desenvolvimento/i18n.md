# Internacionalização (i18n)

[← Índice](../README.md)

O produto usa **dois canais** complementares:

| Canal | Onde | Para quê |
|-------|------|----------|
| SPA (`i18next`) | `frontend/src/i18n/locales/{pt,en,es}/` | Chrome da interface React |
| Django gettext | `backend/locale/` | Mensagens de sistema (erros API, e-mails, admin) |
| CMS `*_en`/`*_es` | modelos News, FAQ, Wiki, Roadmap | Conteúdo editorial |

Idiomas de produto: `pt`, `en`, `es` (Django: `pt-br`, `en`, `es`).

## Frontend (SPA)

- Bootstrap em [`frontend/src/i18n/index.ts`](../../frontend/src/i18n/index.ts).
- Preferência: `localStorage` (`pdl.language`) → idioma do navegador → `pt`.
- Seletor: rodapé público, navegação e painel (`LanguageSwitcher`).
- Namespaces: `common`, `public`, `auth`, `panel`, `admin`, `help`.
- O cliente HTTP envia `Accept-Language` conforme o idioma ativo.
- Formatação (`formatCurrency`, `formatDate`, `formatDateTime`, `formatNumber` em
  `frontend/src/lib/formatters.ts`) acompanha o idioma ativo. Não instancie
  `Intl.*` com `pt-BR` fixo nas telas.

### Adicionar strings na SPA

1. Inclua a chave nos três JSON em `frontend/src/i18n/locales/{pt,en,es}/`.
   `src/i18n/panelAdminLocales.test.tsx` falha se `panel` ou `admin` ficar fora de sincronia.
2. Use `useTranslation('namespace')` na tela.
3. Não reintroduza literais de UI nas superfícies já migradas.

## Backend (Django gettext)

- Settings: `LANGUAGES`, `LOCALE_PATHS`, `USE_I18N`, `LocaleMiddleware`,
  `ApiLanguageMiddleware` (ativa a partir de `?lang=` / `X-Language` /
  `Accept-Language`).
- Catálogos em [`backend/locale/{en,es,pt_BR}/LC_MESSAGES/django.po`](../../backend/locale/).
- Helpers: [`backend/common/i18n.py`](../../backend/common/i18n.py)
  (`resolve_language`, `activate_language`, `localized_text`, …).
- Troca de idioma no admin: `POST /i18n/setlang/` (form já presente no template Jazzmin).
- Domínio **sem** import de Django: mensagens PT são msgid; o exception handler aplica
  `gettext` na borda HTTP. O módulo `common/i18n_msgid_catalog.py` espelha mensagens
  de domínio para o `makemessages`.
- Modelos, `AppConfig`, fieldsets do admin, formulários e Jazzmin (`welcome_sign`)
  usam `gettext_lazy`; e-mails de conta usam `gettext` no envio.

### Fluxo de catálogos

```powershell
cd backend
# Extrair novas strings (após marcar com gettext / gettext_lazy na apresentação)
.\.venv\Scripts\python.exe manage.py makemessages -l en -l es -l pt_BR --ignore=.venv
# Traduzir os .po e compilar
.\.venv\Scripts\python.exe manage.py compilemessages -l en -l es -l pt_BR --ignore=.venv
```

Exige GNU gettext (`msgfmt` / `xgettext`) no PATH.

### Conteúdo da API (CMS)

Passe `?lang=en` ou `?lang=es` (omitir = português). Superfícies cobertas:

- FAQ / handbook do Denkynho
- Notícias, wiki e roadmap
- Documentos legais
- Assistente (`language` no body)

Campos vazios na tradução pedida voltam ao português.

## CMS e admin

Modelos possuem campos `*_en` / `*_es` (FAQ, News, Wiki, Roadmap). O Jazzmin agrupa fieldsets EN/ES. Sem tradução automática: a equipe preenche ou usa o bootstrap EN→ES do FAQ.

## Superfícies migradas na SPA

- Shell público e do painel, autenticação, FAQ, Help e chrome do tema portal-v1.
- Público: home, Coming Soon, Info, Rankings, Wiki, News, Roadmap, Legal, Downloads,
  Calendário e ResourceGate (`public`).
- Painel do jogador: dashboard, perfil, conta e segurança, contas Lineage, avisos,
  atendimento, Jogos, Jornada e recompensas, Progresso, Apoiadores e Ficha do personagem
  (`panel`: `games`, `rewards`, `progress`, `supporters`, `character`).
- Administração: central de módulos, relatórios operacionais e financeiros e fila de
  chamados (`admin`: `hub`, `reports`, `support`).
